# 2026-11-12

## SwiftFormat 集成方式改造 + 授权弹窗修复

- 内置 SwiftFormat 由 0.54.5 升级到 0.64.6，版本记录在 `SwiftFormat.version`。
- 新增 `scripts/update-swiftformat.sh`：一条命令下载指定 tag 并同步 3 个目录
  （`MyPlugin/SwiftFormat/` 核心库+Store、`MyPlugin/ExtensionOnly/` 扩展专用 3 文件、
  `XcodePlugin/SwiftFormat/` 配置 UI），支持 `--latest` / `--current`；
  `SwiftFormat-patches/` 用于保存对上游源码的本地改动，同步后自动覆盖回去。
- Xcode 工程 `objectVersion` 60→70，两个 SwiftFormat 目录改成
  `PBXFileSystemSynchronizedRootGroup`，上游增删文件自动进 target，不再需要手改
  `project.pbxproj`（备份 `/tmp/project.pbxproj.bak`，迁移脚本 `/tmp/migrate_pbxproj.py`）。
- 跨版本 API 适配要点：
  - `format()` 返回 `(tokens, changes)`，取 `.tokens`
  - `parseConfigFile()` 返回 `[[String: String]]`，取 `.first`
  - `allRules.subtracting(FormatRules.disabledByDefault)` → `defaultRules`
  - 项目自有 `Regex` / `CommandLine` 会遮蔽标准库同名类型：`Regex`→`LegacyRegex`，
    `CommandLine`→`CommentLineCommand`（同步改了 Info.plist 的命令类名）
  - 上游 `Sources/CommandLine.swift` 与项目 `MyPlugin/CommandLine.swift` 同名会让 Xcode
    生成冲突的 `.stringsdata`，更新脚本自动给冲突文件加 `SF-` 前缀
- 授权弹窗（macOS「访问文件/文件夹」）：`FormatCode.formatWith` 原本把 uncrustify 临时文件
  写到 `.documentDirectory`（受 TCC 保护的 ~/Documents），改为沙盒容器内
  `FileManager.default.temporaryDirectory`；appex entitlements 移除
  `com.apple.security.files.user-selected.read-write`（宿主 App 保留，导入/导出配置要用）。
- 验证：Debug / Release 全量 `xcodebuild` 均 `BUILD SUCCEEDED`。
- 0.64.6 新增规则/选项的中文文案已在第二轮补齐（见下）。

## 第二轮：汉化补齐 + MARK 空行规则

- 发现升级覆盖了项目自有的汉化改动：原 `UserSelection.swift` 有 `chineseHelp`
  （`NSLocalizedString(title)`），两个 cell view 会优先显示中文。已基于 0.64.6 文件重建，
  并把 4 个 UI 文件放进 `SwiftFormat-patches/XcodePlugin/SwiftFormat/`，
  每次运行 `update-swiftformat.sh` 会自动覆盖回去。
- 新增 `scripts/sync-localizations.py`：`EXTRA_ZH` 字典维护中文，合并进
  `Localizable.xcstrings`（331 个 UI key 全覆盖，共 332 条），并同步生成
  `en.lproj/Localizable.strings`；`--check` 用于升级后查漏。
  key 规律：规则行 = `rule.name`，选项行 = `descriptor.displayName`（英文原文）。
- `// MARK:` 后空行：SwiftFormat 的 `line-after-marks` 只负责插入、不删除已有空行；
  且 `applyRules` 内部 `sorted()` 会重排规则顺序，直接 append 到 rules 末尾无效
  （blankLinesAroundMark 之后又把空行插回来）。最终方案：`FormatCode.formatSwift` 在
  `format()` 之后单独调用 `applyRules([.removeBlankLineAfterMark], to: output, ...)`，
  规则定义在 FormatCode.swift（删除 MARK 行后连续的 linebreak/space，保留缩进）。
- 独立 swiftc 测试 8 个用例全部通过；Debug / Release 均 BUILD SUCCEEDED；
  重跑一次更新脚本后汉化补丁仍在。
