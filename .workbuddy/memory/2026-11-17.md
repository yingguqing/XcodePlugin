# 2026-11-17

## 修复：SwiftFormat 配置界面改动不生效（App Group 名被升级覆盖）

**现象**：在配置界面把 `indent-case`（缩进 switch case）设为 true，格式化 Swift 时无效果；怀疑是单项配置无效还是整套配置没生效。

**根因**：配置界面（宿主 App XcodePlugin）与格式化扩展（MyPlugin）通过 App Group 共享 UserDefaults，组名由 `UserDefaults.groupDomain` 决定（定义在 `MyPlugin/SwiftFormat/RulesStore.swift`，OptionsStore / AppDelegate 都引用它）。但该文件里的值是 SwiftFormat 上游默认 `com.charcoaldesign.SwiftFormat`，而两个 `.entitlements` 声明的是 `com.yingguqing.xcode.plugin`。组名对不上 → 两边(UserDefaults suite)根本不是同一个容器 → 界面保存的规则/选项扩展读不到，格式化一律用默认值。

git 历史显示：commit c154918（2024-10-31）曾把它改成 `com.yingguqing.xcode.plugin`「修复 AppGroup 数据通信」；但 2026-11-12 升级 SwiftFormat 到 0.64.6 的 commit 0be927e 同步上游源码时又覆盖回 `com.charcoaldesign.SwiftFormat`，且该文件当时没有 patch 保护。所以这是升级引入的回归。

**修复**：
1. `MyPlugin/SwiftFormat/RulesStore.swift:36` groupDomain 改回 `com.yingguqing.xcode.plugin`。
2. 复制一份到 `SwiftFormat-patches/MyPlugin/SwiftFormat/RulesStore.swift`，使 `scripts/update-swiftformat.sh` 每次同步末尾自动覆盖回去（该脚本把 patches 目录按项目根相对路径 rsync 回根目录，最后应用）。

**教训/约定**：凡是改了 `MyPlugin/SwiftFormat/`（上游同步目录）里的任何文件，都必须同时放一份到 `SwiftFormat-patches/` 同相对路径，否则下次 `update-swiftformat.sh` 一定被覆盖丢失。项目自有文件（FormatCode.swift / AppDelegate.swift / storyboard / 汉化）不在同步目录，不受影响。

**还需用户端操作**：重新编译安装 App + 扩展；注意另一坑——若配置界面「推断选项(infer-options)」为开（默认 true），`FormatCode.swift:80` 会用 `inferFormatOptions(from:)` 忽略所有手动设置，此时即使 App Group 修好，手设的 indent-case 仍不生效，需关掉推断选项再设。

## 修复：Xcode 26 编译报 xcstrings「would generate the same symbol」

**现象**：升级到新版 Xcode（本机 26）后编译报几十条 `This string key would generate the same symbol as ...`，全是 `Localizable.xcstrings` 里的 key。

**根因**：Xcode 26 默认开了 `STRING_CATALOG_GENERATE_SYMBOLS`（构建设置里叫 Generate String Catalog Symbols），给每个 key 生成形如 `.indent` 的 Swift 符号。本项目有一批 key 是「规则名 camelCase」和「选项 displayName Title Case」同名，如 `indent`/`Indent`、`acronyms`/`Acronyms`、`contentBuilder`/`Content Builder`，camelCase 化后撞名。两者中文不同（规则 tooltip vs 选项标题），不能删 key。项目全程用 `NSLocalizedString(key, comment: "")` 动态查表，不用生成符号。

**修复**：`XcodePlugin.xcodeproj/project.pbxproj` 两处（项目级 Debug/Release，约 499/561 行）把 `STRING_CATALOG_GENERATE_SYMBOLS = YES` 改成 `NO`。已用 xcodebuild 编译验证 BUILD SUCCEEDED，报错消失。注意：这是 Xcode 26 新设置，老 Xcode 12 不认也无害。

## 修复：macOS 弹窗「"xcode插件"想访问其他 App 的数据」

**根因**：macOS 15+ 对 App Group 容器加了 SIP 保护。group ID 必须「以 team ID 为前缀」或「在 provisioning profile 里」，否则系统判定为访问其他 App 的数据并弹窗。本项目用 Apple Development 签名、无 profile（PROVISIONING_PROFILE_SPECIFIER 为空）、team=F35YF899E4，而 group ID `com.yingguqing.xcode.plugin` 没有 team 前缀 → 主 app 启动和扩展格式化时都弹。

**修复**：group ID 改为带 team 前缀的 `F35YF899E4.com.yingguqing.xcode.plugin`（Apple 文档：带 `<team-id>.` 前缀的 group 无需 provisioning profile，系统只校验前缀与签名 team 匹配）。改了 4 处并保持一致：两个 `.entitlements`、`MyPlugin/SwiftFormat/RulesStore.swift:36`、补丁副本 `SwiftFormat-patches/MyPlugin/SwiftFormat/RulesStore.swift`。entitlements 与源码必须字面完全一致。

**副作用**：换 group ID = 换容器，旧容器里的配置不会迁移，用户重装后需重新设置一次（关推断选项 + 打开 indent-case）。未编译，用户自行编译验证。

注：`SF-CommandLine.swift:791` 的 `com.charcoaldesign.swiftformat` 是命令行独立缓存路径，非 App Group，不用改。
